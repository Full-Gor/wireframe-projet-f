Présentation du dossier





Le dossier professionnel (DP) constitue un élément du système de validation du titre professionnel.
Ce titre est délivré par le Ministère chargé de l’emploi.

Le DP appartient au candidat. Il le conserve, l’actualise durant son parcours et le présente obligatoirement à chaque session d’examen.

Pour rédiger le DP, le candidat peut être aidé par un formateur ou par un accompagnateur VAE.

Il est consulté par le jury au moment de la session d’examen.



Pour prendre sa décision, le jury dispose :

  1. des résultats de la mise en situation professionnelle complétés, éventuellement, du questionnaire professionnel ou de l’entretien professionnel ou de l’entretien technique ou du questionnement à partir de productions.



  1. du Dossier Professionnel (DP) dans lequel le candidat a consigné les preuves de sa pratique professionnelle.



  1. des résultats des évaluations passées en cours de formation lorsque le candidat évalué est issu d’un parcours de formation



  1. de l’entretien final (dans le cadre de la session titre).

Ce dossier comporte :

  • pour chaque activité-type du titre visé, un à trois exemples de pratique professionnelle ;

  • un tableau à renseigner si le candidat souhaite porter à la connaissance du jury la détention d’un titre, d’un diplôme, d’un certificat de qualification professionnelle (CQP) ou des attestations de formation ;

  • une déclaration sur l’honneur à compléter et à signer ;

  • des documents illustrant la pratique professionnelle du candidat (facultatif)

  • des annexes, si nécessaire.

Pour compléter ce dossier, le candidat dispose d’un site web en accès libre sur le site.

Installer environnement de travail



1. Décrivez les tâches ou opérations que vous avez effectuées, et dans quelles conditions :


Dans le cadre de ma formation au PôleS, j’ai installé et configuré l’environnement de développement complet pour le projet MossAir, en autonomie sur un poste Windows. J’ai installé WAMP (Apache + MySQL + PHP 8.2), Symfony 6 via Composer, et VS Code avec les extensions PHP et Twig. J’ai configuré Git pour le versionnement et paramétré le fichier .env avec les identifiants de base de données.


J’ai également appliqué des media queries CSS pour garantir un affichage responsive sur mobile, tablette et desktop, en suivant l’approche mobile-first de Bootstrap 5.3.


Pour lancer le projet en local : démarrage de WAMP, exécution de symfony serve, puis accès au navigateur via l’URL locale. Pour chaque fonctionnalité développée, j’ai utilisé Git (git add, git commit, git push) pour versionner le code.


Git -> installation, push des projets et leur suivi


Base de données MySQL configurée via phpMyAdmin, migrations Doctrine gérées en ligne de commande (php bin/console doctrine:migrations:migrate).





2. Précisez les moyens utilisés :


Logiciels, outils…

VS Code (extensions PHP Intelephense, Twig Language, GitLens), WAMP (PHP 8.2 + MySQL 8.0 + Apache), Symfony CLI, Composer, Git, GitHub pour le versionnement, phpMyAdmin pour la gestion de la base de données, Chrome DevTools pour les tests responsive.

J'ai travaillé en autonomie sur ce projet personnel. J'ai bénéficié de l'accompagnement de mon formateur au PôleS pour les difficultés techniques rencontrées, ainsi que des échanges constructifs avec mes camarades de promotion.

Outils pour retirer les arrières-plans, changer tailles et formats

Exemple n° 1 

Mise en place de base de données relationnelle + SQL



1. Décrivez les tâches ou opérations que vous avez effectuées, et dans quelles conditions :


J’ai conçu la base de données du projet MossAir en plusieurs étapes : d’abord un MCD (Modèle Conceptuel de Données) sur papier pour identifier les entités et leurs relations, puis un MLD (Modèle Logique de Données), et enfin le MPD (Modèle Physique) implémenté dans MySQL.

J’ai défini 6 entités principales : User (id, email, password, roles, adresse), Produit (id, nom, description, prix, stock, categorie), Categorie (id, nom), ImageProduit (id, url, produit), Commande (id, dateCommande, statut, total, user), CommandeProduit (id, quantite, sousTotal, commande, produit).


J’ai utilisé phpMyAdmin pour visualiser et vérifier la structure des tables, effectuer des imports/exports SQL, et tester des requêtes. Les migrations Doctrine ont été générées et exécutées via le terminal (php bin/console doctrine:migrations:migrate).


Création de la base de données mode_tendance dans phpMyAdmin, puis définition des entités Symfony via php bin/console make:entity. Doctrine ORM génère automatiquement les fichiers d’entité PHP avec les annotations de mapping.


Création des entités Doctrine dans le terminal : php bin/console make:entity Produit, puis ajout des champs (nom, description, prix, stock). Les relations OneToMany et ManyToOne entre entités ont été définies avec les annotations Doctrine appropriées.


Commandes Symfony : php bin/console make:entity, make:migration, doctrine:migrations:migrate, make:controller, make:form. Ces commandes CLI structurent l’application et automatisent la génération du code de base.


Les Repository Doctrine encapsulent les requêtes DQL : ProduitRepository::findByCategorie() filtre par catégorie, CommandeRepository::findByUser() récupère l’historique client. Les requêtes préparées protègent contre les injections SQL.


Conformité RGPD : collecte minimale des données (email, adresse), mots de passe hashés avec bcrypt (irréversible), accès aux données personnelles limité à l’utilisateur concerné, possibilité de modification du profil depuis l’espace client.


Tests fonctionnels manuels complets : inscription, connexion, parcours d’achat (catalogue, panier, commande), interface admin (CRUD produits, gestion commandes). Tests de responsive design effectués sur mobile, tablette et desktop via Chrome DevTools.





2. Précisez les moyens utilisés :



MySQL 8.0, phpMyAdmin (interface graphique), Doctrine ORM 2.x (entités, migrations, Repository), Symfony CLI (commandes make:entity, make:migration), draw.io pour les schémas MCD/MLD.



3. Avec qui avez-vous travaillé ?

Travail en autonomie sur la conception de la base de données. Le formateur a validé le schéma conceptuel (MCD) avant l'implémentation. Cette validation a permis d'éviter des erreurs de modélisation coûteuses à corriger.

Exemple n° 2 

Composant métiers côté serveur



1. Décrivez les tâches ou opérations que vous avez effectuées, et dans quelles conditions :


J’ai développé les composants back-end du site en suivant l’architecture MVC de Symfony. J’ai créé 6 contrôleurs principaux : ProduitController (catalogue et détail produit), PanierController (gestion du panier en session), CommandeController (processus de commande), AdminController (back-office, protégé par ROLE_ADMIN), SecurityController (login/logout) et RegistrationController (inscription).


L’architecture MVC Symfony sépare clairement les responsabilités : les entités Doctrine (Modèle) gèrent les données, les templates Twig (Vue) gèrent l’affichage, et les contrôleurs PHP (Contrôleur) orchestrent la logique métier et les requêtes HTTP.



L’interface administrateur offre un tableau de bord complet : CRUD des produits avec upload d’images multiples (entité ImageProduit), gestion des commandes avec changement de statut, liste des utilisateurs inscrits, et statistiques de ventes sous forme de graphique.


Le code back-end est intégralement commenté pour garantir la maintenabilité. L’AdminController est protégé par l’attribut #[IsGranted(‘ROLE_ADMIN’)], bloquant tout accès non autorisé. Les formulaires Symfony intègrent une protection CSRF automatique sur toutes les opérations sensibles.


Les opérations CRUD (Create, Read, Update, Delete) sont implémentées pour les produits, catégories, commandes et utilisateurs. Les formulaires Symfony (ProduitType, RegistrationType) gèrent la validation des données et la protection CSRF automatiquement.


EasyAdmin Bundle configuré pour administrer les entités Produit, Categorie, Commande et User. Personnalisation des champs affichés en liste et formulaire, gestion des statuts de commande, et sécurisation totale par ROLE_ADMIN.





2. Précisez les moyens utilisés :



PHP 8.2, Symfony 6 (framework principal), Doctrine ORM, EasyAdmin Bundle, VS Code, Composer (gestionnaire de dépendances), Postman pour tester les routes, Git pour le versionnement du code.



3. Avec qui avez-vous travaillé ?

Projet développé en autonomie. Le formateur a supervisé l'architecture MVC et validé les choix techniques. J'ai également consulté la documentation officielle Symfony et des ressources en ligne pour implémenter les fonctionnalités complexes.
